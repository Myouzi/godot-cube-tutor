## 4. 方案一：D1 二期 Minkwitz 词表法（离线预计算存盘）——强烈推荐（以 §4.0 前置实验通过为前提）

### 4.0 拍板前置实验（半天级，r2 修订新增，强烈建议拍板前先跑）
D1 的全部实证都在**随机态**层面（spike 200 随机 σ），B0 的 27 个中心段卡点态从未进过原型；「换 seed/调 cap 就能扫中」目前是假设。消掉这个最大不确定性只要半天：
- **做法**：①写临时 GDScript 探针复刻 `_probe_b0_survey.gd` 口径，把 n≥5 全部中心段卡点态（27 个）导出为置换 JSON（`_fb_sigma_of` 同款构造，或直接导出中心 facelets 由 Python 侧算 σ）；②喂给 spike（/tmp/minkwitz_spike.py，本次修订已复核文件仍在，23961 字节——若已被清理则按调研记录重建，构建 n=7 表仅 28.6s）逐态跑 sifting+σ 配对首通率；③输出每阶命中率与失败态的级分布诊断。
- **判读**：27 态首通率高（如 ≥90%）→ D1 确定性升级，按 §4.4 开工；有缺口但失败形态仍是「少数级 trans 缺点」（换 seed/调 cap 分钟级重出表可扫）→ 维持强烈推荐、工期按 3.5-4 天；失败形态指向 σ 配对/奇偶修正结构性不通 → 降级 D1 评级，重议路线（此为唯一能推翻本排序的实验）。

### 4.3 可行性论证
- **数学**：Minkwitz 1998（J. ### 5.2 技术路线的关键修正（本次 godot 实测）
- **要转译的不是 L2E 表的 swap 类公式（结构性无效），而是 wing 3-cycle commutator**。实测依据：双对换宏（moved=4）对 t0 型 inc=0（同色集集合互换无效）；双 3-环宏（moved=6）第二环必拆已配对棱；两者共轭域 660 条新效应对 B0 卡点全零命中（probe4）。修复必须 moved==3 单 3-环。L2E 表的 flip 类属 OLL parity 域，项目已由 PARITY_ALGS 覆盖（nxn_solver.gd:3099-3108）。
- **枚举证伪边界澄清**：§9.4 枚举域 = 外层 setup 18 × 池宏 2440 × 外层 undo（tests/_probe_b1_enum.gd 头注释明示「仅外层(内层切片破坏中心 setwise)」）——**内层切片 commutator 完全在枚举域外，证伪结论不覆盖 B1 增量域**。
- 单 3-环宏存在性已一手实证：核式 `"3R U2 3R' D2 3R U2 3R' D2"`（盲拧 3-style [2R,U2]+D2-interchange commutator 结构）净效果 (1,14,12)、中心 setwise 封闭、wing 封闭，命中 B0 t3 卡点 9→10 对。⚠ 但评审复跑：**1+1+1 型核式单独入池是净负收益——降级态 3→4**（t3 消解但贪心路径漂移产生新 t0 型卡点）；30%→0% **完全押在 t0 型 2+1 支集形态宏的定向构造/收集成功上**（probe8 已锁定剩余缺口 = t0 型 2+1 形态）。

### 7.4 段间接口不变量与「正交」的准确边界（r2 新增，回应读者）
- **「正交」的准确表述**：三案**收益分块正交**（D1 只改中心段数据源、B1 只加 4 阶组棱池、B2 只改 5-7 阶组棱搜索，治理的降级态互不重叠，收益可叠加、无实施先后依赖），**但不是工程隔离**——三案改的都在同一个 `nxn_solver.gd`，共享段管道与断言面。
- **段间为什么不会互相漂移（结构依据）**：降阶法是串行段管道，**下一段消费的是上一段的输出态（facelets），不消费上一段的解序列**——`tests/_probe_b0_survey.gd:24-34` 即此接口的实证写法：`solve_centers(fs)` → 把解 `_apply_alg` 到打乱态副本 → `solve_edges(sim)` 只拿 `sim`。因此一段内部的宏池/换表变化（B1 入池、D1 换表、B2 宽轮）只要不破坏该段的输出契约（段末验证/终验通过才返回 ok），就不会改变下一段的搜索输入语义；B1 的「贪心路径漂移」（probe7）发生在**组棱段内部**（新宏改变同段贪心择优），不是跨段漂移。各案已各自把段内漂移列为验收项（B1 门 1 级联全通、B2 收口语义对齐+下游稳定性断言）。
- **真实的跨案交互面（验收断言层，须串行处置）**：①S9/CN_KEY_LOCK（test_server.gd:22-26）锁中心段卡点 key——D1 换表会改中心段解序列（key 变化=引擎行为变化，按 EXPERIENCE.md:33 流程先确认 key 本体再处置）；B1/B2 若修复的卡点恰被 S9 覆盖也会翻锁。②TNE/TNC 系 DEGRADED-RATIO 断言面（现状均为 print 统计，各案均为新增硬断言）。③PARITY_FIX A/B、B0 探针等共享口径。**结论：收益正交可并行开发，断言翻转（S9 锁值更新/断言新增）必须串行处置，不并行改同一测试文件。**
